## 1. Executive Summary

This investigation establishes the definitive runtime signal surface of Google Antigravity (AGY CLI `v1.2.2`, ARM64 ELF static Go binary) running in the real PocketShell Linux guest environment on Android (Galaxy Tab S7 SM-T870).

### Key Ground-Truth Findings:

1. **The Definitive Waiting Signal (Case B):**
   When AGY completes an LLM response and awaits user input, it emits an exact 40-byte in-band terminal burst:
   ```
   07 1b 5d 39 3b 41 6e 74 69 67 72 61 76 69 74 79 20 43 4c 49 20 69 73 20 72 65 61 64 79 20 66 6f 72 20 69 6e 70 75 74 07
   ```
   This burst consists of:
   - Byte 0 (`0x07`): Standalone ASCII BEL character (`\a`), alerting the terminal bell.
   - Bytes 1..39: iTerm2 OSC 9 notification sequence: `\x1b]9;Antigravity CLI is ready for input\x07`.

2. **The Non-Interactive Stream (Case A):**
   When invoked with `-p <prompt>` in a non-interactive shell, AGY emits **zero escape sequences, zero BELs, and zero OSC notifications**. It streams the plain text response directly to stdout terminated by `\r\n`.

3. **No External Notification IPC:**
   Binary string analysis, symbol disassembly, and system call tracing (`strace`) prove that AGY contains **zero references to `notify-send`** and **zero D-Bus calls to `org.freedesktop.Notifications`**. AGY communicates user-attention requests exclusively through the in-band PTY byte stream.

4. **Root Cause of False `NEEDS_INPUT` (Attention) During Active Execution:**
   - **Race Condition in Main Thread Queue:** The terminal emulator processes output in 64 KB chunks (`TerminalSession.java`). It invokes `onBell` synchronously inside `mEmulator.append()`, calling `touchBellPulse()` which stamps `bellAtMs = now`. Simultaneously, `onNotification` (from OSC 9) posts to `mainHandler` with `mainHandler.post { touchBellPulse(id) }`, stamping `bellAtMs` on a *subsequent* event loop tick. Because `AgentRuntimeEvents.kt` evaluates `attention = bellAtMs != null && bellAtMs >= lastOutputAtMs`, any `bellAtMs` timestamped on a later tick than `touchOutputPulse` forces `attention = true` even if output was actively drawn in the same repaint frame.
   - **End-of-Turn Interactive Re-prompt:** AGY is an iterative conversational agent. At the conclusion of *every* turn, query, or sub-task, it returns to the interactive prompt and emits `\a\x1b]9;Antigravity CLI is ready for input\a`. If a background process or sub-task is still active while the main session waits for the user's next directive, the agent is reported as `NEEDS_INPUT` because the top-level CLI is genuinely awaiting user instruction.

5. **Root Cause of Lingering `NEEDS_INPUT` After Input is Provided:**
   - **Input Echo Latency vs Reduction Window:** When the user types into PocketShell, characters are piped into the PTY stdin via `TerminalSession.write()`. Stdin writes do *not* touch `lastOutputAtMs`. Only *pty output* (via `onTextChanged` -> `touchOutputPulse`) updates `lastOutputAtMs`. In non-TUI mode or when cloud LLM inference takes 5–12 seconds, zero bytes are emitted to PTY output during thinking. If `bellAtMs` was set prior to typing, `bellAtMs >= lastOutputAtMs` remains `true` throughout the entire inference period!
   - **`bellAtMs` is Never Reset:** There is no mechanism in `TerminalSessionManager` or `AgentRuntimeEvents` to clear `bellAtMs = null` upon user input. `bellAtMs` can only be superseded by a newer `lastOutputAtMs > bellAtMs`.

## 2. Investigation Methodology & Instrumentation Setup

To capture raw signals without distortion, a multi-layer instrumentation harness was built and executed in the real guest environment:

1. **PTY Tap Instrumentation (`scratch/pty_capture.py` & `/tmp/agy_capture2.py`):**
   A dedicated Python-based pseudo-terminal (pty) master/slave harness that attaches AGY to a full virtual terminal (`TIOCSWINSZ` 40 rows x 180 cols, `TERM=xterm-256color`), capturing every raw byte with microsecond monotonic timestamps into:
   - `/tmp/agy_cap2.raw`: Verbatim byte stream.
   - `/tmp/agy_cap2.ann`: Human-readable annotated log tagging all CSI, OSC, BEL, and control bytes.

2. **System Call Tracing (`strace`):**
   `strace -e trace=write,sendto,sendmsg,execve,socket,connect -f -s 200` to monitor:
   - D-Bus socket activity (`/run/user/.../bus` or `/var/run/dbus/system_bus_socket`).
   - Execution of external notification binaries (`notify-send`).
   - Internal file descriptor redirections.

3. **Kernel & Process State Inspection (`/proc/<pid>/`):**
   Sampling `wchan`, `status`, `task/<tid>/wchan`, and `fd/` of AGY across startup, generating, waiting, and exit states.

4. **Binary Static Disassembly & Symbol Analysis:**
   Direct binary scanning of `/opt/agy/antigravity` (203 MB aarch64 ELF) inspecting Go packages:
   - `google3/third_party/jetski/cli/...`
   - `google3/third_party/gemini_coder/...`
   - `google3/third_party/jetski/cortex/...`

## 3. Signal Channel 1: PTY Byte Stream

### 3.1 Raw Hexdump of the Attention Burst
At the exact transition where AGY finishes its turn and requests input, the following 40 bytes are written to the slave PTY:

```hexdump
00000000: 071b 5d39 3b41 6e74 6967 7261 7669 7479  ..]9;Antigravity
00000010: 2043 4c49 2069 7320 7265 6164 7920 666f   CLI is ready fo
00000020: 7220 696e 7075 7407                      r input.
```

### 3.2 Breakdown of Escape Sequences
1. **Byte 0: `0x07` (`BEL` / `\a`)**
   - Standard ASCII Bell.
   - Causes terminal emulators to trigger auditory/visual bell or `sessionClient.onBell()`.
2. **Bytes 1–39: `\x1b]9;Antigravity CLI is ready for input\x07` (`OSC 9`)**
   - Introducer: `\x1b]` (OSC - Operating System Command, code 9).
   - Payload: `Antigravity CLI is ready for input`.
   - Terminator: `\x07` (BEL used as OSC String Terminator `ST`).
   - In iTerm2 / ConEmu / Ghostty / Termux protocols, OSC 9 displays a desktop notification with the specified text.

### 3.3 Progress Sequences in Binary (`OSC 9;4`)
Static binary inspection reveals that AGY implements iTerm2 progress reporting protocols:
- `\x1b]9;4;0\x07` — Clear progress bar (task complete / idle).
- `\x1b]9;4;1;\x07` — Indeterminate progress spinner.
- `\x1b]9;4;2;<val>\x07` — Percentage progress bar.
- `\x1b]9;4;3\x07` — Error state progress.

### 3.4 Interactive TUI Control Sequences (CSI)
During active generation, AGY streams:
- Braille spinner glyphs: `⣾` (`\u28fe`), `⣷` (`\u28f7`), `⣯` (`\u28ef`), `⣟` (`\u28df`), `⡿` (`\u287f`), `⢿` (`\u28bf`), `⣻` (`\u28fb`), `⣽` (`\u28bd`).
- Cursor control: `<CSI:?25l>` (hide cursor), `<CSI:?25h>` (show cursor), `<CSI:2A>` (cursor up 2 lines), `<CSI:K>` (clear line).

## 4. Signal Channel 2: Standard Streams (stdout vs stderr)

### 4.1 TUI Mode File Descriptor Redirection
When launched in an interactive terminal:
- **`fd 0`**: Open to `/dev/pts/X` (PTY slave for user input).
- **`fd 1` (stdout)**: **Redirected by AGY** to internal session log: `/root/.gemini/antigravity-cli/log/cli-YYYYMMDD_HHMMSS.log`.
- **`fd 2` (stderr)**: **Redirected by AGY** to the same session log file.
- **`fd 9` & `fd 10`**: Duplicated `/dev/pts/X` fds opened specifically for raw terminal drawing.

**Consequence:** Standard unix redirection (`agy > out.txt 2> err.txt`) does not capture TUI drawing, and standard stream inspection reveals nothing about active state. All user interactions occur directly on the PTY slave fd.

### 4.2 Non-Interactive Mode (`-p`)
When invoked as `agy -p "<prompt>"`:
- `fd 1` is preserved as stdout.
- Response is written directly to `fd 1`.
- `fd 2` receives glog-formatted diagnostics (`I0913 ... server.go:1560] Starting language server...`).

## 6. Signal Channel 4: Filesystem, State DB, & Local IPC

1. **SQLite Database:** `conversation_summaries.db` (with `-wal` and `-shm` files).

3. **Local Loopback Ports:**
   - AGY language server listens on two random unprivileged TCP ports (e.g. `localhost:45521` for HTTPS/gRPC and `localhost:37811` for HTTP).
   - No Unix domain sockets or named pipes are created in `/tmp` or `/run`.

## 10. Root Cause Analysis: Why False `NEEDS_INPUT` Occurs in PocketShell

### Analysis of the Race Condition:
1. When AGY emits the 40-byte attention burst:
   ```
   \x07\x1b]9;Antigravity CLI is ready for input\x07
   ```
2. `TerminalEmulator.append()` processes bytes synchronously on the main thread:
   - Byte 0 (`0x07`): Calls `mSession.onBell()` -> `touchBellPulse(id)` -> `bellAtMs = System.currentTimeMillis()`.
   - Line 351 (`notifyScreenUpdate()`): Calls `onTextChanged()` -> `touchOutputPulse(id)` -> `lastOutputAtMs = System.currentTimeMillis()`.
   - Byte 1..39 (`OSC 9`): Calls `mSession.onNotification()`.
3. In `TerminalSessionManager.kt`:
   ```kotlin
   onNotification = { title, message ->
       mainHandler.post {
           touchBellPulse(id) // <-- POSTED TO HANDLER QUEUE!
           ...
       }
   }
   ```
4. **The Flaw:** `touchBellPulse` is posted to `mainHandler`! When `mainHandler` processes this block on the *next tick* of the looper, `System.currentTimeMillis()` has advanced by 1–5ms.
5. Consequently, `bellAtMs` is stamped with a timestamp **greater than** `lastOutputAtMs`.
6. In `AgentRuntimeEvents.kt`:
   ```kotlin
   val attention = pulse.bellAtMs != null && pulse.bellAtMs >= pulse.lastOutputAtMs
   ```
   Because `bellAtMs > lastOutputAtMs`, `attention = true` is declared, triggering `WorkingChanged(attentionRequested=true)` and posting the Android notification `Antigravity requests attention`.

## 11. Root Cause Analysis: Why `NEEDS_INPUT` Lingers After Input

### Analysis of the Input Path:
1. When the user types into PocketShell to answer a prompt:
   - Keystrokes travel: `TerminalView` -> `TerminalSession.write()` -> Linux PTY slave.
   - **PTY input writes do not invoke `touchOutputPulse()`**.
2. If the agent takes time before emitting output (e.g. LLM inference, API latency, network lag, or a silent build tool):
   - `lastOutputAtMs` remains at the old timestamp prior to user input.
   - `bellAtMs` remains at the old timestamp set during the previous prompt.
   - Because `bellAtMs >= lastOutputAtMs` remains true, the agent remains locked in `attentionRequested = true` (`NEEDS_INPUT`) while the user is actively waiting for the model!
3. Even worse: If the user backgrounded PocketShell while typing, `onTextChanged` repaints may be throttled or deferred by Android, preventing `lastOutputAtMs` from updating promptly.

## 12. Terminal Emulator & PTY Protocol Boundaries

| Signal | Linux Guest Emits | Termux Emulator Layer | PocketShell Session Client | Android Shade Delivery |
| :--- | :--- | :--- | :--- | :--- |
| **ASCII BEL (`0x07`)** | `0x07` written to PTY | `TerminalEmulator.java:283` calls `mSession.onBell()` | `PocketShellSessionClient.onBell()` | `TerminalSessionManager.touchBellPulse()` |
| **OSC 9 (Notification)** | `\x1b]9;<msg>\x07` | `TerminalEmulator.java:2038` calls `onNotification("Terminal", msg)` | `PocketShellSessionClient.onNotification()` | Stamped via `mainHandler.post` to `NotificationCoordinator` |
| **OSC 777 (rxvt-unicode)** | `\x1b]777;notify;<t>;<m>\x07` | Parsed at line 2040, calls `onNotification(t, m)` | Handled via same lambda | Dispatches to Android notification shade |
| **OSC 9;4 (Progress)** | `\x1b]9;4;<state>\x07` | Not currently parsed by `TerminalEmulator` | Dropped at emulator boundary | Ignored |
| **CSI Sequences** | Colors, cursor, screen | Rendered into screen character buffer | Screen update callback | Stamped via `touchOutputPulse()` |

## 14. Architectural Recommendations for PocketShell M7.2 Reducer (Future Work)

*(Note: Per user constraints, these recommendations are documented for architectural planning only and are NOT implemented in this commit.)*

1. **Clear Bell on Stdin Input:**
   In `TerminalSession.write(byte[] data, ...)`: When the user enters data into the terminal, PocketShell should invoke `TerminalSessionManager.clearBellPulse(id)` or touch an `inputPulse(id)`. This immediately breaks the `bellAtMs >= lastOutputAtMs` hold the instant the user presses Enter.

2. **Deduplicate `onBell` and `onNotification`:**
   Because AGY emits `\x07` and `\x1b]9;...\x07` simultaneously in the exact same packet, `touchBellPulse` is called twice within 2 milliseconds. `onNotification` should update the notification text without scheduling a delayed `touchBellPulse` that races the output clock.

3. **Incorporate OSC 9;4 Progress Awareness:**
   Teaching `TerminalEmulator.java` to parse `OSC 9;4;0` (clear) and `OSC 9;4;1` (indeterminate progress) would give PocketShell a 100% authoritative in-band signal of when the agent is actively executing vs done, completely eliminating heuristic timeouts (`WORKING_WINDOW_MS = 5000ms`).

4. **Synchronize Output and Notification Timestamps:**
   Remove `mainHandler.post` delay from `touchBellPulse` in `onNotification`. Use a unified monotonic timestamp source for all pulses.
