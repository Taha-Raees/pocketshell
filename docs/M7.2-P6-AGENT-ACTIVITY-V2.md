# M7.2 P6 — AGENT ACTIVITY v2

Agent A (Kilo Code), branch `agent-A/m7.2-notifications`. Extends the
P0–P9 architecture with the states the mission names, on NEW authoritative
evidence. Full rationale: `.kilo/plans/m7.2-agent-activity-v2.md` (audit §0).

## 1. The core correction

The P0 premise — "the agent's exit status is structurally discarded" — was
voided by P9: `AgentLaunchRecords` wraps launcher agents and records the
agent's own `$?` into `ExitRecord`. That fact was read every 2 s tick into
`Observation.lastExit` and then dropped. P6 surfaces it.

## 2. States and their sole evidence

| State | Evidence |
|---|---|
| 🟢 RUNNING | /proc correlation or anchor (P3b, unchanged) |
| 🟡 WORKING | RUNNING ∧ output within 5 s (PTY output-recency fact) |
| 🟠 ATTENTION_REQUESTED | terminal bell after the agent's last output (the program itself requested attention; cleared by next output) |
| 🔵 EXITED_SUCCESS | `ExitRecord(0)` — the agent's own waitpid-grade status |
| 🔴 EXITED_FAILED | `ExitRecord(n)` , n ∉ {0} ∪ 128..191 |
| ⚪ EXITED_STOPPED | `ExitRecord(128+n)` (130=SIGINT, 143=SIGTERM) |
| ❓ UNKNOWN / NOT_RUNNING | unchanged P3b contracts (typed agents still end as NOT_RUNNING — no record channel) |

Still banned: silence-based "needs input", screen-text parsing,
keystroke inference (P0 Tier 3).

## 3. Implementation (all event-driven; zero new polling)

- `AgentRuntimeDetection`: `EXITED_SUCCESS/FAILED/STOPPED` states derived
  from the record channel (launch record must exist; terminal-sticky;
  survive failed /proc scans).
- `AgentRuntimeEvents`: `AgentExited(exitStatus)` + `WorkingChanged(active,
  attentionRequested)` events; `SessionActivityPulse` input; reducer arms
  (edge-only activity, terminal dedup, activity cleared on every
  transition out of RUNNING).
- `TerminalSessionManager`: coalesced (1 Hz) `activityPulses` StateFlow fed
  by the existing screen-update callback + a new bell lambda
  (`PocketShellSessionClient` stays a clean PTY adapter — no
  detection/notification symbols; the waiting-evidence boundary holds).
- `AgentRuntimeEventEngine`: third combined flow, same sequential reducer.
- `AgentRuntimeNotificationMapping`: record-backed one-shot exit
  notifications ("finished successfully" / "failed (exit code N)" /
  "was stopped"), in-place activity refinement of a posted running surface
  (never standalone), and suppression of the session-exit line when the
  agent's own exit was already announced.
- Home claims: `EXITED_SUCCESS/FAILED/STOPPED` ("— Finished / — Failed /
  — Stopped"); activity grades stay notification-only this increment
  (documented deferral — needs the pulse flow wired into Home).

## 4. Structural-test revisions (conscious, per-file justification)

The P0 wording ban rested on the voided premise. Revised: transition
matrix (new exit/activity arms; RUNNING/UNKNOWN surfaces keep their bans),
event vocabulary 5→7 kinds (invented-certainty identifiers still banned),
Home claims vocabulary + SessionsSection literals (the three record-backed
exit literals exempted from the finish/failed ban — everything else still
banned), waiting-evidence boundary (client-symbol ban kept; the lambda
seam documented), LaunchIdentity seam list unchanged (new types live
inside the existing seam files).

## 5. Performance

1 Hz pulse coalescing; bell emits immediately (latency-sensitive);
/proc tick unchanged (2 s, parks when idle); notifications in-place with
`setOnlyAlertOnce`; exit notifications one-shot. No new timers, threads,
or observers.
