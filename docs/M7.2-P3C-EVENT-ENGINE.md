# M7.2 P3c — Agent Runtime Transition & Event Engine

Phase status: **complete** (internal infrastructure phase — no user-visible
change, no device gate required). Chain: `f782272` (implementation + tests)
→ documentation commit → worklog record. The delivered artifact is the git
bundle cut at the record tip; the APK was built and audited at the inherited
stamp but is not the delivery vehicle (see TESTING §52).

```text
P3a  Trusted launch identity      (what the session was LAUNCHED as)
P3b  Runtime observation          (RUNNING / UNKNOWN / NOT_RUNNING / NOT_APPLICABLE)
P3c  Trusted runtime transitions  (DEDUPLICATED STRUCTURED EVENTS)   ← this phase
```

## 0. The one-sentence contract

PocketShell can now truthfully say, internally and exactly once per fact:
"agent X was launched in session N", "agent X is confirmed running (these
pids, this grade)", "agent X stopped being detected", "agent X's runtime
became unknown", "the session that launched agent X ended" — and NOTHING in
this phase posts an Android notification.

**This phase does not post Android notifications.** It creates no channel,
requests no permission, touches no toast/snackbar/dialog/screen, and adds no
UI. It is the typed event substrate the future notification system will
subscribe to.

## 1. Event vocabulary (Part D — the smallest honest set)

```text
sealed class AgentRuntimeEvent            (terminal/AgentRuntimeEvents.kt — PURE)
├─ Launched          "a known-agent launch appeared"       — the P3a spawn fact
├─ ConfirmedRunning  "process evidence proves RUNNING now" — the P3b fact + pids + grade
├─ NoLongerDetected  "the tracked process is gone"         — proven absence ONLY
├─ RuntimeUnknown    "the evidence cannot prove a state"   — honest uncertainty
└─ SessionEnded      "the session reached a terminal edge" — the P2 session fact
```

Every event carries the full identity block — `sessionId` plus the typed
`LaunchIdentity.KnownAgent` snapshot (`launcherId` is the stable key; the
display name rides along for humans and is never used as identity) — and
`occurredAtMs` (passed INTO the pure reducer; no clock inside the model).
The state-transition events additionally carry the transition origin:

| Event | Extra fields | Answers "which transition?" via |
|---|---|---|
| `Launched` | — | appearance in the manager's authoritative state |
| `ConfirmedRunning` | `from: AgentRuntimeState?`, `evidence: ProcessEvidence` | `from` = last EVENT-derived state (null = birth); evidence = the exact pids + match grade |
| `NoLongerDetected` | `from: AgentRuntimeState`, `lastEvidence: ProcessEvidence?` | the state it left + what used to match |
| `RuntimeUnknown` | `from: AgentRuntimeState` | the informative state it left |
| `SessionEnded` | `cause`, `sessionExitStatus: ExitStatus?`, `lastState` | `SESSION_FINISHED` (waitpid-proven direct-child exit) or `SESSION_REMOVED` (tab closed) |

Registry knowledge is REUSED, never duplicated: the identity is the P3a
`LaunchIdentity.KnownAgent`, the evidence is the P3b
`AgentRuntimeDetection.ProcessEvidence`, the exit status is the P2
`ExitStatus`, the runtime states are the P3b `AgentRuntimeState`.

## 2. The exact transition matrix (Part E)

Derived from three inputs, all authoritative-state-backed (no /proc access
anywhere in this layer):

```text
TerminalSessionManager.sessions        (StateFlow — launches, liveness, endings)
RuntimeAgentDetector.observations      (StateFlow — the four-state contract)
```

SessionsChanged input:

| Transition | Event | Repeat? | Trust |
|---|---|---|---|
| live KnownAgent id never tracked | `Launched` | once per session | spawn truth (P3a) |
| tracked id now FINISHED (in list) | `SessionEnded(SESSION_FINISHED, status)` | once | waitpid-proven (P2) |
| tracked id gone from the list | `SessionEnded(SESSION_REMOVED, null)` | once | the manager's own removal |
| id already ended | nothing, ever | — | terminal memory |

ObservationsChanged input (tracked, not-ended sessions only):

| Transition | Event | Repeat? | Trust |
|---|---|---|---|
| birth → UNKNOWN (first scans) | **none** — the baseline is silent | n/a | detector uncertainty, not a transition |
| UNKNOWN → RUNNING | `ConfirmedRunning(evidence)` | once per entry | process evidence (P3b) |
| RUNNING → RUNNING | **none** (evidence refreshes silently) | n/a | dedup (Part F) |
| RUNNING → NOT_RUNNING | `NoLongerDetected(lastEvidence)` | once per entry | proven absence — **NOT completion** |
| NOT_RUNNING → NOT_RUNNING | **none** | n/a | dedup |
| NOT_RUNNING → RUNNING | `ConfirmedRunning` again | a new meaningful transition | reappearance is real |
| RUNNING → UNKNOWN | `RuntimeUnknown` | once per entry | honest uncertainty |
| UNKNOWN → UNKNOWN | **none** (no event storm) | n/a | dedup |
| NOT_RUNNING → UNKNOWN | `RuntimeUnknown` | once per entry | evidence turned ambiguous |
| UNKNOWN → NOT_RUNNING | `NoLongerDetected` | once per entry | only reachable from an evidence-holding UNKNOWN |
| null → NOT_RUNNING | **none** (structurally impossible per the P3b decision table; defensive skip) | n/a | never fake an absence |
| RUNNING (null evidence) | **none** (defensive: no claim without a process) | n/a | never claim without evidence |
| → NOT_APPLICABLE | **none** (never published for eligible sessions) | n/a | non-agents never enter this layer |

## 3. Deduplication behavior (Part F)

The detector polls every ~2 seconds; the engine must not become an event
firehose. The guarantee, pinned by pure tests:

```text
same state observation  =  no duplicate event
```

One entry of in-memory `AgentRuntimeEventMemory` per LIVE tracked session
holds the last state an EVENT was derived from (null until the first event)
plus the most recent evidence. The subtlety that keeps the model honest:
`lastState` tracks **events, not raw observations** — the silent
birth-UNKNOWN never becomes the `from` of a later story, and an absence can
never be derived from a state that was never announced. Ended session ids
move to a terminal set (bounded by the number of agent sessions in the
process lifetime); the memory is process-scoped, in-memory, and never
persisted — this layer is not a database.

## 4. Session ownership (Part E.5 — one authority, honored)

`TerminalSessionManager` remains the ONE lifecycle authority. The engine
derives terminal edges from the manager's authoritative state itself — a
FINISHED phase is visible on the entry (with its waitpid status), and a
removal is the entry leaving the list — so session death is noticed from
session truth, never by waiting for a future /proc tick. The engine mutates
nothing upstream: no `_sessions` write, no `closeSession`, no
`markStarted/markFinished`, no `_observations` write. Its only wake site is
the manager's spawn path, beside the detector's (`ensureStarted`,
idempotent) — the same "wake your observers" pattern P3b established.

## 5. Stale-observation handling (Part G)

The forbidden sequence — session closed, then a stale detector RUNNING
result arrives, then "agent confirmed running" — is structurally rejected:

1. **Sequential processing**: ONE collector coroutine folds BOTH StateFlows
   through the pure reducer, so an observation can never interleave with
   the terminal edge that invalidates it.
2. **The staleness gate**: an observation for an untracked (never-an-agent,
   non-agent) or already-ended session is rejected outright — no memory
   mutation, no event.
3. **StateFlow inputs**: the engine's first collection delivers the CURRENT
   authoritative state; a restarted engine synthesizes no events for
   transitions it never observed.

The honest residual: because StateFlow conflation is real, a session whose
entire spawn→(finish)→removal completes before the engine's first
collection, or within one conflated dispatch, yields no events — the
authoritative session state remains the reconciliation truth (the manager's
buffered `lifecycleEvents` SharedFlow exists for consumers needing raw
edges; P3c chose state-derived transitions for their race-safety).

## 6. What P3c events PROVE

- That a session with a known-agent launch identity exists (spawn truth).
- That a correlated process matching the agent's launch token is running
  RIGHT NOW — with the pids and grade that caused the claim.
- That a previously-observed process is no longer detected — proven
  absence, explicitly not success, not failure, not completion.
- That the runtime evidence currently cannot prove a state (UNKNOWN).
- That the session (the direct child / the tab) reached a terminal edge —
  a session fact with the session's own exit status.
- That each of these facts CHANGED at a specific point in time, exactly
  once per change.

## 7. What P3c events do NOT prove

- That an agent COMPLETED, SUCCEEDED, FINISHED, or produced useful work —
  the vocabulary contains no such event, and `NoLongerDetected` must never
  be re-labeled as one. Completion detection belongs to a later phase, on
  evidence this architecture does not have (the agent's own exit status is
  structurally discarded by the launch chain — P3a truth-loss point 3).
- That an agent is waiting for input, idle, or "working" (the P0 audit's
  Tier-3 rejections stand).
- Anything about custom tools, known non-agent tools, or plain shells —
  they never enter this layer (the same P3a/P3b eligibility line).
- Anything about processes outside a session's fork-proven tree (P3b's
  correlation boundary, inherited untouched).

## 8. The future notification consumer boundary

The notification system (a later phase, NOT started) subscribes to
`AgentActivityRepository.agentRuntimeEvents` and needs to understand NONE
of: `/proc`, process groups, PID ancestry, agent token matching, polling
intervals, scan failures, zombie states, or lifecycle transition rules.
Those details stay behind P3b and the pure reducer. The stream's guarantees
the consumer may rely on:

- every emission IS a transition (state is never re-published as event);
- no replay: a collector that (re)subscribes starts from NOW — activity
  recreation or a restarted collector never re-fires old events;
- identity is complete in every event (no by-id re-lookup needed);
- `ConfirmedRunning` always carries the process evidence behind it;
- `NoLongerDetected` and `SessionEnded` are distinct, and neither implies
  completion;
- drops are possible only beyond the 64-event buffer with no collector
  keeping up, and are logged — never silent.

Policy (which events warrant which notification) is the consumer's job,
not this layer's.

## 10. Known limitations (honest, each by design)

1. **Conflation window**: a session whose entire spawn→removal (or
   spawn→finish→removal) completes before the engine's first collection or
   within one conflated StateFlow dispatch yields no events — the
   authoritative session state is the reconciliation truth (§5).
2. **Best-effort edges**: event delivery beyond the 64-event buffer with no
   keeping-up collector is dropped-with-log, not persisted — the same
   stance as the manager's own lifecycle-event stream.
3. **`from` is event-relative**: it names the last state an EVENT was
   derived from, not every silent intermediate observation (by design —
   the consumer's story must never include states it was never told).
4. **No persistence**: events are process-scoped, like the sessions
   themselves; a process death ends the story (the terminal FGS makes that
   exactly as long as the sessions' lifetime).
5. **No waiting-for-input, no completion** — permanently out of scope until
   a phase brings real evidence for them.
