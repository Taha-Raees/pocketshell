## 2. Feature record — Agent A File Explorer (M7.2-A workstream)

Commit 080a6b9 on `agent-A/m7.2-file-explorer`, merged as 7c01a21.

### 2.1 Clickable breadcrumbs
- `files/Breadcrumbs.kt` (pure): one crumb per ancestor of the validated
  `AreaPath`; root crumb labeled with the AREA's short label ("Linux",
  "Downloads", granted-folder name) — never a fake POSIX root for SAF
  areas; current location rendered (not a button).
- Tap targets in the location row (horizontal strip, auto-scrolls to the
  current crumb); a tap navigates through `ExplorerCore.openDirectory`
  with the crumb's OWN validated `AreaPath` — no string reassembly, no
  filesystem work beyond the single listing of the target. The up
  affordance and system-back behavior are unchanged.

### 2.2 Open in Android app
- Reuses the Phase 5 share-staging discipline: the file is copied into
  `cacheDir/share/` and handed out as a FileProvider `content://` URI
  (authority `app.pocketshell.fileprovider`) with a temporary read-only
  grant; `ACTION_VIEW` launched through an explicit chooser. The real
  filesystem path never leaves the app.
- The ViewModel probes `resolveActivity` BEFORE staging (targetSdk 28 is
  exempt from Android 11+ package filtering) and surfaces the honest
  "No installed Android app can open …" notice when nothing matches.
- Works for every storage area (staging goes through `StorageArea.openRead`).

### 2.3 ZIP compress / extract
- `files/ZipArchiveOps.kt`, built on commons-compress 1.28.0 (already a
  pinned dependency — no new libraries). Streaming only through the
  `StorageArea` abstraction: identical behavior for guest Linux, the
  Downloads shelf, and SAF document trees.
- Compress: single entry, multi-selection (selection-bar "Zip"), folders
  with structure preserved; directory entries are STORED with known
  zero sizes/CRC so no data descriptors are ever written (maximum
  compatibility, and commons-compress's backward end-of-archive scan
  never mistakes a trailing DD for a split marker).
- Extract: destination is an editable folder name inside the current
  directory (created when missing); implied parent directories are
  created for archives without explicit directory entries.
- Safety contract (pinned by ZipArchiveOpsTest):
  - entry names validated BEFORE creation — Zip-Slip (../, absolute,
    NUL, dot components) refuses the whole operation fail-closed and
    names the offending entry;
  - NO silent overwrites: existing targets are skipped and reported;
    overwriting requires the explicit "Replace existing files" choice;
  - symlinks are never archived (skipped with warnings);
  - archive-bomb caps (2 GiB extracted / 100k entries) enforced
    mid-entry, not only between entries;
  - compress writes through the area's atomic write session — a failed
    or cancelled compress keeps NO archive; the committed size is
    verified against the bytes written;
  - ZIP magic pre-check so a non-zip file is refused honestly;
  - cooperative cancel with an honest partial result (entries and bytes
    extracted so far).
- UI: action-sheet "Compress" (files + folders), "Extract…" (zip files),
  selection-bar "Zip"; name/destination dialogs with inline errors;
  cancellable progress banner (determinate only when a total is really
  known). Archive work runs on its own serial worker so a long
  compress/extract never delays navigation (the search-worker pattern).

## 5. Known limitations (honest)

- "Open / inspect archive contents in place" is not implemented — a zip
  file's in-app inspection is Extract-driven; "Open in Android app" is
  offered for zip files where an external handler exists.
- Symlinks are never archived (skipped, warned) — a zip cannot represent
  a PocketShell symlink honestly under this safety contract.
- Multi-select ZIP is reached from the selection bar; the per-entry sheet
  compresses one entry at a time (matching the sheet's single-entry
  contract).
- `agent-B/m7.2-notifications` remains unmerged; when it lands, rebase it
  on this main (expected conflicts: none — disjoint files; versionCode
  will need a fresh bump).
- The 4 pre-existing unit-test failures above belong to the runtime /
  observation suites and predate this integration.
